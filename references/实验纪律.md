# 实验纪律

对应 SKILL 第 8–12 步。四条硬规矩：

1. **快：** 日常迭代以秒到分钟计；做不到就缩，缩不了就换题（视频1、视频3）。
2. **先预测：** 每个被批准的实验开跑前，人和 AI 各写一份预测和理由；写不出就不跑（视频1、视频3）。
3. **意外是课题：** 结果和预测不符，写成新问题（视频1、视频3）。
4. **先小后大：** 小规模成立再放大；放大不成立就追问「什么变了」（视频4）。

## 1. 预测表模板

跑之前填前六列，跑之后填后三列。

| 实验 | 只改的因素 | 我的预测（带数字或方向） | 理由（机制） | 把握 | AI 的预测与理由 | 实际结果 | 是否意外 | 下一步 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| E1 | | | | % | | | 是 / 否 | |
| E2 | | | | % | | | | |

填写要求：

- 预测要能被结果推翻。「会有影响」不算预测，「指标 X 至少下降 40%」才算。
- 人先写，再让 AI 写，不要先给 AI 看你的预测。
- 两份预测不一致的地方，开跑前讨论一次。
- 写不出预测：不跑，先补理解（再读论文、问 AI 机制、做一个更小的检查）。
- 意外时在「下一步」写新问题，不要只写「重跑」。

文件版见 [templates/预测表.md](../templates/预测表.md)。

## 2. 快速小实验的设计套路

### 2.1 通用规则

- **只改一个因素**，其他全部固定（模型、数据、提示、种子集合）。
- **最小规模起步：** 小模型、短序列、合成数据、少量步数。
- **程序判分：** 答案由程序生成，判分确定，不用 LLM judge。
- **样本量和种子：** 每个条件至少 3 个种子或给误差线；行为实验每个条件几百个样本。
- **单次耗时：** 先估算一次。超过几分钟就先缩。
- **先跑通 r=0 / 无干预条件：** 确认基础任务准确率够高，再加干预。

### 2.2 视频里出现过的形状（视频3 课题表，未核实具体结果）

| 形状 | 例子 |
| --- | --- |
| 扫一个超参数 | 在小模型上扫 Muon 的批大小和动量 |
| 记录一条曲线 | 记录每个 token 的损失，找出何时下降 |
| 换一个设置再跑一遍 | 分别用 RoPE 和无位置编码训练 |
| 测一个内部量 | 在训练早期测量曲率与损失；测量每个位置的梯度大小 |
| 改一个数值精度 | 用 float64 训练，看损失尖峰会不会消失 |
| 改一个规模档位 | 在几种模型大小下比较 1 步和 10 步 |
| 构造成对提示 | 为小模型做 50 对只换动词的提示 |
| 去掉一部分再训 | 正常训练一次，去掉 value 和 output 更新里的弱方向再训一次，比较（视频4） |

### 2.3 Agent 方向常用的两种框架（本 skill 实际用过）

**预填历史 + 只生成下一步。** 用程序构造一段 agent 历史（系统提示、若干轮用户 / 助手 / 工具消息），只让模型生成下一步，再自动判分。

- 一个数据点只要一次很短的生成。
- 只改历史中的一个因素，其他不变，构成严格受控对比。
- 判分确定，不需要 LLM judge。
- 例：查表加法任务，在 20 轮历史里按比例 r 注入固定样式的错误（每次都恰好多 10），看新错误是否复现这个样式。

**合成环境。** 写一个几十行的小环境，动作和反馈都可控。

- 例：40 个文件里找一把钥匙；6 个组件里找出故障的那个。
- 用来先测信号（例如模型在「看见失败反馈」和「看不见失败反馈」时输出分布差多少），再决定要不要上 ALFWorld、WebShop 这类真实基准。

模型建议（写作时的常见开源选择）：Qwen3-0.6B / 1.7B / 4B，复核用 Llama-3.2-1B/3B 或 Gemma-3。具体运行时间必须实测，未测前一律写「估算」。

## 3. 跑完之后

1. 把结果填进预测表，标出意外。
2. 对每个意外问两句：我为什么会那样预测？为什么实际是这样？
3. AI 的每次解释记进研究日志，标「错误 / 不完整 / 与之前矛盾」（视频1 图解）。
4. 论文和 AI 都解释不清的地方，写成下一个问题（视频1：理解的极限就是研究起点）。
5. 一周至少一次用自己的话重述机制。

## 4. 放大检验

### 4.1 什么时候做

- 小规模上结论成立：达到预测阈值，跨种子稳定。
- 已经排除了最强的竞争解释（例如视频4 的「不只是训练得更少」对照：把普通模型提前停在相同损失，再比较）。

### 4.2 怎么做

- 只改规模：宽度、层数、训练步数、模型大小。视频4 画面的档位是宽度 48 → 64/96/128、步数 250 → 1,000 → 4,000（未核实）；agent 方向可以用 0.6B → 1.7B → 4B。
- 每档先预测。
- 每档用同一套判分和同样的种子数。

### 4.4 不成立时

- 不放弃，追问：为什么不成立？大了之后什么变了？让 AI 一起分析（视频4）。
- 回到小规模，造一个能复现「大了之后的变化」的条件，在小规模上找原因。
- 能写成随规模变化的规律最好；写不成，就如实写「只在小规模上成立」。

### 4.5 时间纪律

放大检验可以等一两个小时（视频4），但只是少数几次。不要因此把日常迭代都变成长时间任务（张力 1）。

## 5. 报告数字的规矩

- 实测的数字写设置（模型、数据、种子数、误差）。
- 没实测的写「预测」或「估算」，例如「单卡 24GB 约 1–2 天（估算）」。
- 不把视频画面上的数字（3.9 秒、65% / 97%、250 步等）当基准或证据引用。
