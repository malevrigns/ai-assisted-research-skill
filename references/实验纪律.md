| 干预 | | | | | |

先运行最小样本，检查数据、指标方向和输出。尽量用相同的测试样本和匹配的种子，固定数据切分、评估规则和预算。涉及训练时保存数据版本、依赖、配置、命令和检查点。复现已有工作时列出原文设置和无法对齐的配置。

按最小有意义的效应、方差和预算选择样本量。报告适合设计的不确定性，例如独立训练的种子间变化或配对样本的区间。单次试跑标为探索性。日常对照优先缩到可以快速重复的规模。稳定信号出现后再安排较长的复验。

| 研究问题 | 可用的最小检查 |
| --- | --- |
| 现象何时出现 | 用固定验证集测多个检查点，记录指标随训练变化的曲线 |
| 哪个超参影响现象 | 一次改变一个超参，保持训练预算与数据一致 |
| 改进来自哪个组件 | 去掉一个组件，用同一评估重复比较 |
| 损失尖峰是否来自数值精度 | 在同一个最小设置比较不同精度，固定其他条件 |
| 代理是否利用失败反馈 | 构造成对历史，只改反馈信息，只生成下一步并自动判分 |
| 干预是否只是增加训练量 | 对齐数据量、训练步数或计算预算后比较 |
| 现象是否依赖任务复杂度 | 在可控合成环境调节一个难度因素，记录失效边界 |

成对历史适合先测某段反馈是否改变动作分布。合成环境适合控制动作有效性、反馈和状态重放。两者都先确认基线能完成基本任务，并检查自动判分的边界情况。

## 事前预测

用 [预测表](../templates/预测表.md) 记录各条件主指标方向或区间、机制理由、证伪条件和无法判断的情况。标清不同解释预期出现的结果。用户已经给出预测时记录两份判断，说明是否独立形成。若两份预测不同，先把分歧转成可检验的对照。

运行检查、探索性实验、确认性实验分别标记。运行检查记录实现与输出是否正常。用于检验主张的数据收集前先固定主要判断标准。已经看过结果的解释记作事后假设，并留出独立复验。

## 解释意外

1. 比较实际结果和预测，核对数据切分、基线、指标、实现和不确定性。
2. 若实现和评估正常，列出几种竞争解释。每种写一个有区分力的最小对照。
3. 在 [研究日志](../templates/研究日志.md) 记录证据、原解释与新解释的冲突，以及当前支持、反对或无法判断的结论。
4. 同时推进多条实验线时，用同一版本的主张。每条线记录要检验的解释、当前结果和下一步。

## 放大与复验

有稳定的小规模信号后，选与主张最相关的泛化维度，例如模型宽度、训练步数、数据量或任务难度。尽量一次只变一个维度。更换模型同时改变架构或预训练数据时，记录差异并缩小推断范围。复用指标和判分，运行前记录每档预测。
