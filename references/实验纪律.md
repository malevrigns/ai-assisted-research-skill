# 实验纪律

| 排除替代解释的对照 | | | | | |

先运行最小样本检查数据、指标方向和输出是否正确。需要比较两个条件时优先用同一批测试样本和匹配的种子。涉及训练时记录数据切分、检查点、依赖版本、配置和命令。复现已有工作时记录上游版本、报告的设置，以及任何无法对齐的配置。

按效应大小、方差和预算确定样本量。报告适合设计的不确定性，例如独立训练的种子间变化或配对样本的区间。若只能跑单次，把结果标为探索性。

| 研究问题 | 可用的最小检查 |
| --- | --- |
| 训练何时出现某个现象 | 保存固定时间点的检查点，记录同一验证集上的指标曲线 |
| 改进是否来自某个组件 | 关闭该组件，保持训练预算和判分一致 |
| 代理是否利用失败反馈 | 在合成环境构造成对历史，只改反馈信息，自动判分下一步 |
| 干预是否只是增加训练量 | 对齐数据量、训练步数或计算预算后比较 |

## 预测和结果判定

运行前在 [预测表](../templates/预测表.md) 记录机制理由、预期方向或阈值、证伪条件。先约定什么会导致无法判断，例如基线无法正常运行或区间太宽。用户提供预测时分别记录其预测和助手预测，并说明两者是否独立形成。

将意外结果依次和数据切分、基线、指标、实现及方差核对。若实现正常，列出能产生不同预测的竞争解释。把看到结果后形成的解释写成待复验假设，留出独立的验证数据或条件。

## 放大与复验

有稳定的小规模信号后，选与主张最相关的泛化维度，例如规模、任务或数据集。尽量一次只变一个维度。若更换模型同时改变了训练数据或架构，记录这种差异并缩小推断范围。复用指标和判分，运行前记录每个档位的预测。

放大结果不一致时，报告成立的条件和失效的边界。从计算预算、数据分布和任务难度中找能用小实验区分的解释。
