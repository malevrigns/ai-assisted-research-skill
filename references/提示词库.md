# 提示词库

本文件收齐 SKILL.md 每一步的提示词，按步骤编号。方括号 `[ ]` 是要替换的内容。

- **原句**：视频里画面或口播出现过的提示词，照抄，标出处。
- **加强版**：在原句上补齐本 skill 的规矩（近半年、大公司单独标、不编造、标明估算）。
- 提示词可以短，但边界必须清楚（张力 3）。

---

## P0 把兴趣说成一个问题（第 0 步）

```text
我对 [大致方向] 感兴趣，但还说不清想研究什么。
请问我 5 个问题，帮我找出我真正好奇的机制或现象。
每次只问一个问题，等我回答后再问下一个。
最后用一句话写出「我想弄懂的是：……」，不要替我选题。
```

## P1 检索往届会议论文（第 1 步）

**原句（视频3 画面）：**

```text
帮我找 NeurIPS 等往届会议上关于语言模型如何学习的论文。
```

**加强版：**

```text
帮我找 [NeurIPS / ICML / ICLR] 等往届会议上关于 [主题] 的论文。
1. 先列最近 6 个月的，再另列更早的经典工作，两组分开。
2. 每篇给：标题、第一作者、arXiv 编号或会议链接、一句话讲它做了什么。
3. 作者来自 Google/DeepMind、OpenAI、Anthropic、Meta、Microsoft、阿里、字节、DeepSeek 等大公司的，单独标出，依据是论文署名。
4. 不确定是否存在的论文不要列；列出来的每一篇都必须能打开。
```

**读论文辅助：**

```text
我正在读《[标题]》（[链接]）。请用三句话回答：
1. 它解决了什么问题；
2. 它用什么实验证明，最关键的一张图或表是哪个；
3. 它自己在 Limitations / Future work 里承认还留了什么。
只根据原文回答，引用原文的节号。读不到原文就直接说读不到。
```

## P2 把论文变成最小检查（第 2 步）

```text
我刚读完《[论文标题]》（[链接]）。
请从里面挑出 3 个可以在笔记本或单卡上、几秒到几分钟内复现或对照的现象。
每个给出：
- 要观察的量（例如某条曲线、某个比例）
- 最小对照（只改一个因素）
- 需要的模型规模和数据规模
- 预计耗时（标明是估算）
不要设计需要大集群的实验。
```

## P3 出点子（第 3 步）

**P3-A 原句（视频1 画面，中文字幕版）：**

```text
我在为ICML 2027写论文，方向是LLM预训练，也许还有优化器。给我一些关于大语言模型预训练和优化器的点子。也许还有智能体，也许还有安全。我就是想看看所有的点子。
```

**P3-B 原句（视频2 Prompt 1）：**

```text
Give me one research idea about large language model pretraining.
```

**P3-C 加强版（列清单 + 先综述）：**

```text
我在为 [会议+年份] 写论文，方向是 [方向1]，也许还有 [方向2]、[方向3]。
给我所有你能想到的研究点子。
要求：
1. 先检索文献，只给还没人做过的，或把几篇已有工作组合成新东西的。
2. 每条一行：一句话问题 | 为什么可能没人做过 | 最接近的已有工作（不确定写「不确定」）| 最小实验需要多大算力。
3. 优先「理解机制」类的问题，不要只能靠堆算力才看得到现象的。
4. 可以读我的笔记：[笔记内容或路径]。
```

**P3-D 「需要算法」变体：**

```text
在 [方向] 上给我 5 个带算法的研究点子。
每个点子必须有：一句话方法、目标函数或伪代码、它针对的已知失败现象（附论文链接）、最接近的方法和区别。
[免训练 / 需要训练]，算力 [……]。
```

**并行设置（视频2 设置栏）：** 模型 = 最新模型；Agents = 6 个独立；Effort = Default；Could read = My notes。

## P4 按算力和三条标准初筛（第 4 步）

```text
下面是候选点子清单：[粘贴]。
我的算力是 [笔记本 / 一张 24GB 卡 / ……]。
对每条判断：
1. 最小能看到现象的实验要多大模型、多少数据、多长时间（标明估算）
2. 这是「理解机制」类还是「堆算力 / scaling」类
3. 按三条标准各给 是/否/不确定：还没被深入理解？够深，一篇讲不完？能快速迭代？
4. 保留还是淘汰，一句话理由
做不动的直接标淘汰；第一眼「太简单」但能往下挖的，标保留并写出可以往下挖的方向。
```

## P5 查新（第 5 步）

**原句（视频2 Prompt 2）：**

```text
Check whether your idea already exists somewhere. Search properly, read the closest papers, then answer yes, partly or no, and name the closest paper and what it leaves open.
```

**加强版：**

```text
检查这个点子是否已经有人做过：[一句话点子 + 方法草图]。
1. 检索至少用 arXiv 和另一个来源（Semantic Scholar / Google Scholar / OpenReview），列出你用的检索词（至少 5 组，含同义词和英文术语）。
2. 主窗口是最近 6 个月，但也要回查更早的工作。
3. 回答格式：
   - 结论：yes / partly / no
   - 最接近的 1–3 篇：标题、arXiv 编号、日期、作者单位（大公司单独标）
   - 每篇和本点子相同的地方、不同的地方
   - 它留下的缺口：具体到一个可以做的实验
   - 你的依据来自全文还是摘要
4. 你没打开过的论文不许写进来；不确定的编号写「未核实」。
```

**逐篇全文核对：**

```text
请读这篇论文的全文：[链接]，重点看方法、实验、消融和附录。
回答：
1. 它是否已经做了「[本点子的关键操作]」？原文哪一节？
2. 它的设置（单轮/多轮、训练/免训练、任务类型）和本点子有什么不同？
3. 它的结果里有没有直接否定本点子预测的数据？
4. 如果我做本点子，审稿人会不会说「这就是 [该论文] 的简单扩展」？怎么反驳？
只引用原文，给出节号或图表号。
```

**撞车周检（做的过程中每周一次）：**

```text
在 arXiv 上搜过去 7 天的论文，检索词：[……]。
有没有和「[一句话结论]」直接撞车的？有就给编号、标题和重合程度（完全 / 部分 / 只是相关）。
```

## P6 审稿打分和追问（第 6 步）

**打分：**

```text
你是 ICML 审稿人。请评审下面这个研究点子：
[一句话问题 + 方法草图 + 查新结论和最接近的论文]

按三项分别打 1–10 分，并给出理由：
- Soundness：假设和实验设计是否合理、逻辑是否自洽，能否真正检验这个结论
- Originality：和最接近的论文相比，新在哪里（已有工作覆盖的部分不算新）
- Significance：做成之后，谁会用、会改变什么做法

再给出：
- 最可能导致拒稿的 3 个问题
- 每个问题对应的、能补救的最小实验
- 如果你是作者，第一周应该做什么
```

**追问：**

```text
你给 [某项] 打了 [X] 分。
1. 具体是哪一点让你扣分？
2. 要做到 [X+2] 分，需要补什么实验或论证？
3. 我不同意你的这一点：[理由]。请重新评估，如果仍然坚持，说明原因。
```

**讨论实验的问法（视频2 示意对话）：**

- 「你觉得 [因素] 会影响什么？」
- 「你确定吗？我不这么认为。」
- 「能再解释一下吗？你为什么觉得会这样？」
- 「我们能设计什么实验来检验这个假设？」
- 「这个怎么测量？」
- 「你怎么知道这不是问题所在？」

## P7 收成一句话（第 7 步）

```text
我选定的点子是：[……]。
请帮我把它收成一句可检验的结论，要求：
1. 一句话，能当论文标题
2. 只涉及一个部件或一个设置
3. 写出一个能推翻它的实验结果（带阈值）
4. 写出一个最强的竞争解释，以及排除它的对照
给 3 个版本，从最窄到稍宽。不要扩展到别的问题。
```

## P8 设计最小实验（第 8 步）

```text
我的一句话结论是：[……]，只看 [部件]。
请设计一个最小对照实验：
- 只改一个因素：[……]，其他全部固定
- 最小模型规模和数据规模，目标是单次运行在 [笔记本 / 单卡] 上 [几秒到几分钟]
- 判分方式（优先程序判分）
- 每个条件的种子数和样本量
- 估算单次和总耗时（标明是估算）
写出完整的实验条件表。先不要写代码，等我确认。
```

**原句参考（视频3 口播大意）：** 让 Opus 写一个带标准组件、用 Muon 的小 LLM，做五秒钟的实验。

## P9 让 AI 预测（第 9 步）

```text
实验设计如下：[条件表]。
在看到任何结果之前，请预测：
1. 每个条件下主要指标的大致数值或方向
2. 你的理由，具体到机制
3. 你有多大把握（百分比）
4. 哪个结果会让你最意外
不要写代码，不要运行，只写预测。
```

**原句参考（视频3）：** 「你觉得这个实验会发生什么？」

## P10 解释意外、抓矛盾（第 10 步）

```text
我预测 [……]，实际结果是 [……]。
1. 列出 3 种可能解释这个差异的机制。
2. 每种机制各给一个能区分它和其他机制的小实验。
3. 你之前说过 [AI 之前的解释]。如果这次结果和它矛盾，请直接指出哪里矛盾，不要圆回去。
```

**抓矛盾的一句话（视频3）：** 「等一下。你刚才说会发生相反的事。这是怎么回事？」

**追到边界：**

```text
关于 [现象]，请分三栏列出：
1. 已有论文已经解释清楚的（附出处）
2. 已有论文给了说法但证据不足的
3. 目前没人能解释的
第 3 栏每条给一个能在小规模上检验的实验。
```

## P11 让 AI 保持专注（第 11 步）

**每步一句话汇报规则（放进系统提示）：**

```text
本项目只研究一句结论：[一句话结论]。
范围：只看 [部件]。不做与这句结论无关的实验，不扩大范围，不改结论措辞，除非我同意。

每一步开始前，先用一句话回答：
「我接下来要做 [具体动作]，因为它能检验 / 排除 [结论中的哪一点或哪个竞争解释]。」
每一步结束后，用一句话回答：
「结果是 [数字或现象]，它 [支持 / 反对 / 无法判断] 这句结论。」
如果你想做的事情说不清和这句结论的关系，停下来问我，不要做。
每个新实验开跑前，先写预测和理由，等我批准。
不要替我写整篇论文。
```

**原句（视频4 画面）：** 「我告诉它：用一句简单的话解释下一步。」

**拉回正轨：**

```text
我不同意你刚才这一步：[……]。
它和「[一句话结论]」没有直接关系。请回到 [部件]，下一步只做 [……]。
先用一句话说你下一步做什么，再开始。
```

## P12 放大检验（第 12 步）

```text
结论 [……] 在 [小规模设置] 上成立，证据是 [……]。
请设计放大检验：
1. 只改规模的 2–3 个档位
2. 每档的预测和理由
3. 如果在大规模上不成立，列出 3 个「什么变了」的候选，以及分别检验它们的实验
4. 估算每档耗时（标明是估算）
```

## P13 写作与五项检查（第 13 步）

**五项检查：**

```text
下面是我的研究短文草稿：[粘贴]。
按五项逐条检查，每项给「达到 / 部分 / 未达到」和具体修改建议：
1. 连贯：每一节是否都服务于标题那句结论
2. 全面：是否覆盖了主实验、对照、消融、放大和局限
3. 解释清楚：读者能否不看代码复述方法
4. 站得住脚、讲得通：每个结论是否有对应证据，有没有过度推断
5. 是否新：和最接近的论文相比，新在哪一句
最后列出最该补的 3 件事，按优先级排序。不要改写全文。
```

**只改一段（不让 AI 写整篇）：**

```text
只改这一段：[粘贴]。保留所有真实数字和限定语，不新增实验或结论。
改完用一句话说明你改了什么。
```

**原句参考（视频4 画面上的 15 条清单的提示词）：** *your advice for the next 5 years PhD student, no explanations*
