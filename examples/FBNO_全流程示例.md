# 全流程示例：FBNO（失败反馈盲负例优化）

本示例用本 skill 实际跑出的一个点子，把 SKILL.md 的第 0–14 步走一遍。

**先说清楚哪些是真的、哪些是计划：**

- 第 1–7 步和第 14 步是实际做过的：检索、出点子、查新、打分、选定、交付。论文编号来自 arXiv API 的实际返回，最接近的 5 篇读了全文。
- 第 8–13 步是**计划**。还没有跑任何实验。下文所有成功率、下降幅度、运行时间都是**预测或估算**。

## 第 0 步：心态与起点

- 用户的大方向：LLM 智能体（agent）。
- 好奇的问题：「agent 为什么会重复已经失败过的动作？它看见了失败反馈，为什么不用？」
- 条件：一个人做，算力有限（笔记本或一张中等 GPU），目标 ICML 2027 或同级会议。

## 第 1 步：定领域，找相近论文

- 领域：LLM agents。在 14 个子方向上检索了近半年（2026-05 至 2026-11）的论文：记忆、工具调用与技能库、长程执行与上下文压缩、可靠性与失败归因、多智能体、agent 强化学习、规划与搜索、自我改进等。
- 渠道：arXiv 官方 API（主窗口近半年，查新不限日期），加 Semantic Scholar 查引用链。约 400 条摘要缓存到本地 JSON，方便复查。
- 大公司工作单独列了一节；只标注署名核实过的论文。

读到的关键现象（与本点子相关的两篇）：

- [2509.09677](https://arxiv.org/abs/2509.09677)：自我条件化——模型会照抄自己之前的错误。
- [2611.13254](https://arxiv.org/abs/2611.13254)：失败轨迹里 72% 已经出现过反证，其中 88% 被忽略。

## 第 2 步：读完就动手

从这两篇抽出一个能马上检查的现象：**同一个历史，遮掉失败观察和不遮，模型下一步动作的分布差多少？** 这可以用「预填历史 + 只生成下一步」在小模型上测，每个数据点一次短生成（耗时是估算，未实测）。

最接近的 5 篇读了全文：

| 论文 | 结论 | 相同 | 不同 / 缺口 |

## 第 6 步：打分与实验取舍

| 项 | 分 | 理由 |
| --- | --- | --- |
| 严谨性 | 7 | 有核实步骤、有随机负例消融、有机制指标（JSD）；风险是重放核实要求确定性环境 |
| 原创性 | 6 | 机制上接近「SSFO 搬到多轮 agent + 环境核实」 |
| 重要性 | 7 | 直接针对「agent 不用失败反馈」这一广泛现象，且作为辅助损失容易接进现有 RL 框架 |

人做的实验取舍（示范写法）：

- 做：随机负例消融（检验 H⁻ 是否关键）。
- 做：和「GiGPO + 重复 / 无效惩罚」对比（检验是否只是更贵的去重）。
- 不做：在 SWE 环境上的主实验——环境不确定，重放核实做不了，先不碰。

## 第 7 步：收成一句话

```text
标题：在 agent RL 中，用「失败反馈被抹掉时才会选的、经核实会失败的动作」作负例，能让策略真正依赖失败反馈，而不只是减少重复。
范围：只看动作 token 的概率；只用确定性环境（合成环境、ALFWorld）。
当前把握：约 60%（主观）。
证伪条件：不比 GiGPO + 重复/无效惩罚强（差距在种子方差内）；或随机负例效果一样；或 JSD 上升但成功率不变。
最强竞争解释：效果只来自「多了一些负例 / 多了正则」，与 H⁻ 无关 → 对照：负例改从 π(·|H) 随机采。
```

## 第 8 步：最小实验（计划）

- **合成环境：** 40 个文件里找钥匙；6 个组件里找故障。失败反馈明确、可重放。
- **只改一个因素：** 是否加 L_FB；消融里只改负例来源。
- **判分：** 程序判分（成功与否、重复失败次数）。
- **模型：** Qwen3-0.6B 调参，LoRA + vLLM。
- **第一步先测信号：** 训练前，在失败步上测 JSD(π(·|H) ‖ π(·|H⁻))。如果几乎为 0，说明小模型本来就不读反馈，负例没意义，要先换 1.7B。
- **耗时：** 0.6B 合成环境约 1–3 小时（估算）。

## 第 9 步：预测（跑之前写）

| 实验 | 预测 | 理由 | 把握 |
| --- | --- | --- | --- |
| 训练前 JSD（0.6B，失败步） | 明显大于 0（若接近 0，负例无意义，改用 1.7B） | 模型多少会读反馈，但读得不够 | 55% |
| ALFWorld unseen，1.7B，FBNO vs GiGPO | 高 3–6 个百分点 | 负例直接针对忽略反馈的那部分概率质量 | 55% |
| 重复失败率 | 下降 50% 以上，比加重复惩罚的版本至少多降 2 个点 | 重复惩罚只压已采样的重复，FBNO 压反事实惯性动作 | 60% |
| 随机负例消融 | 收益不到 FBNO 的一半 | 如果 H⁻ 是关键，随机负例不针对惯性 | 60% |
| 训练过程中 JSD | 上升 | 损失把 π(·|H) 推离 π(·|H⁻) | 65% |

（把握数字是主观估计，示范写法。）

## 第 10 步：跑完对照（计划）

预先写好的「意外」处理：

- 如果 JSD 上升但成功率不变：说明模型学会了「和不看反馈时不一样」，但不一定是「更好」。下一步看被压低的动作去了哪里——是换成了有用动作，还是换成了另一种无效动作。
- 如果随机负例同样有效：H⁻ 不是关键，结论要改成「额外负例正则」，回到第 7 步改那句话。

需要训练的算法我选了 **FBNO（失败反馈盲负例优化）**，它是 RL 训练里加的一个辅助损失。查新时最接近的 5 篇论文都读了全文，没找到相同的做法。还没跑过实验，下面的数字都是预测或估算。

**一句话**
把历史里的失败反馈抹掉，让模型生成动作；再到环境里核实这个动作确实会失败；然后在完整历史下压低它的概率。这样训练是为了让 agent 真正依赖失败反馈，不再按惯性重复已经失败过的动作。

**算法**
记号：H_t 是完整历史。H⁻_t 是把之前的失败观察换成占位符、动作原样保留后的历史。

$$L = L_{\text{GRPO/GiGPO}} + \lambda L_{FB}$$

$$L_{FB} = -\log\sigma\Big(\beta\big[(\log\pi_\theta(a^+|H_t)-\log\pi_{ref}(a^+|H_t)) - (\log\pi_\theta(a^-|H_t)-\log\pi_{ref}(a^-|H_t))\big]\Big)$$

a⁺ 和 a⁻ 都在同一个完整历史 H_t 下比较，只算动作 token。没有 a⁺ 时改用 unlikelihood，即对 a⁻ 的每个 token 取 −log(1−π)。

每轮训练的步骤：

```
1. π_old 采样 G 条轨迹，照常算 GRPO/GiGPO 优势
2. 选出前面已有 ≥1 次失败的步，每个 batch 最多 K 个
3. 对每个选中的步 t：
     构造 H⁻_t，采样 m 个 a⁻ ~ π_old(·|H⁻_t)
     核实：只保留会失败的 a⁻（与已失败动作相同，或重放到 s_t 执行后失败）
     难负例：只保留 π_θ(a⁻|H_t) ≥ p_min 的
     a⁺ = 同一状态下优势 > 0 的动作（GiGPO 的 step group）
4. 用 L_GRPO + λ·L_FB 更新；π_ref 每 R 轮同步一次
```

超参：m 取 2–4，K 取 8–32，λ 取 0.1–0.5，β=0.1，p_min=0.05。

**为什么有效**
- 已知现象：模型会照抄自己之前的错误（[2509.09677](https://arxiv.org/abs/2509.09677)）；失败轨迹里 72% 已经出现过反证，其中 88% 被忽略（[2611.13254](https://arxiv.org/abs/2611.13254)）。
- 原理：π(·|H⁻) 正好代表「不看失败反馈时的惯性行为」。拿这部分里经过核实的错误动作当负例，梯度会把 π(·|H) 推离 π(·|H⁻)，也就是加强动作对失败反馈的依赖，而不是简单地压低所有重复。
- 环境核实保证不会误伤合理的重复。

**和已有工作的区别**
- [SSFO 2508.17225](https://arxiv.org/abs/2508.17225) 是思想上最接近的。它在 RAG 场景用「有/无上下文」的输出组 DPO 对，并默认有上下文的输出更好。FBNO 的不同有三点：多轮 agent 场景且只抹失败观察；负例要经环境核实；作为在线 GRPO 的辅助损失，而不是离线 DPO。
- [CVT-RL 2606.05263](https://arxiv.org/abs/2606.05263) 干预的是动作，然后续跑估计这个动作的因果贡献，用来分配功劳。FBNO 干预的是历史里的失败观察，用来造负例。
- [SERL 2605.19447](https://arxiv.org/abs/2605.19447) 用 teacher 看到的未来反馈（特权信息）给优势重新加权。FBNO 不用特权信息。
- [EFCA 2608.08255](https://arxiv.org/abs/2608.08255) 和 [2610.25957](https://arxiv.org/abs/2610.25957) 给已采样到的重复或无效动作扣标量奖励。FBNO 挖的是没采样到的反事实负例，并在 token 级做对比。这两篇是**最关键的基线**。

**实验**
- 环境：先用合成环境（40 个文件找钥匙、6 个组件找故障）调参，0.6B 约 1–3 小时；主实验是 ALFWorld 的 seen 和 unseen，基于 [GiGPO](https://arxiv.org/abs/2505.10978) 的开源框架；WebShop 可选。
- 模型：Qwen3-0.6B 和 1.7B，用 LoRA 加 vLLM，有余力再做 4B。
- 基线：ReAct、GRPO、GiGPO、GiGPO 加重复/无效惩罚、GiGPO 加 EFCA 式奖励、把 SSFO 直接移植到多轮（不核实）。
- 消融：去掉核实；负例改从 π(·|H) 随机采；抹掉全部观察；DPO 换成 unlikelihood；λ、m、K 的取值。
- 指标：成功率（3 个 seed）、重复失败率、无效动作率、步数、失败步上的 JSD(π(·|H)‖π(·|H⁻))。
- 时长（估算）：1.7B 在 ALFWorld 跑一组，单卡 24GB 约 1–2 天，2–4 张卡约 0.5–1 天；每轮额外计算约 10–25%；全部做完约 2–3 周卡时。

**预测与证伪**
预测：1.7B 在 ALFWorld unseen 上比 GiGPO 高 3–6 个百分点；重复失败率下降 50% 以上，比加重复惩罚的版本至少高 2 个百分点；随机负例的收益不到 FBNO 的一半；JSD 随训练上升。

出现以下任一情况，这个想法就不成立：
- 不比 GiGPO 加重复/无效惩罚强（差距在 seed 方差以内），说明它只是更贵的去重。
- 随机负例效果一样，说明 H⁻ 不是关键。
- JSD 上升但成功率不变。

**打分与风险**
打分是严谨性 7、原创性 6、重要性 7。原创性只有 6，是因为机制上接近「SSFO 搬到多轮 agent 加环境核实」。

风险：
- 重放核实要求环境是确定性的，网页和 SWE 环境很难做到。
- 0.6B 可能本来就不读反馈，那 H 和 H⁻ 的输出几乎一样，负例就没有意义。所以第一步先在合成环境测 JSD。
- 负例少的时候，这个损失会很稀疏。
- 方向很热，撞车风险高，要尽快在合成环境做出结果。

**备选：EIR-PO（注入错误前缀的 RL）**
训练时以概率 p，把 k 个经过核实的失败动作和真实的失败反馈重放进 rollout 前缀，然后从这个「被污染」的状态继续跑 GRPO。奖励看最终是否成功，再加上「之后不再重复被注入的动作」的奖励，让模型练习从照抄错误的状态里走出来。实现更简单，打分 6/5/6，不过只做了摘要级查新。
